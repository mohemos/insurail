# Insurail — marketing site

Single-page marketing website for **Insurail**, the embedded microinsurance API for Africa, starting in Nigeria.
Built with Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Framer Motion and Lucide. Deploys to Vercel as a
statically pre-rendered page plus one serverless function for the lead form.

- Copy lives in one place: [`content/site.ts`](content/site.ts)
- Design tokens live in one place: [`app/globals.css`](app/globals.css) (see [`DESIGN.md`](DESIGN.md))
- SEO and accessibility verification: [`CHECKLIST.md`](CHECKLIST.md)

## Quick start

```bash
pnpm install
cp .env.example .env.local   # optional: lead delivery + analytics
pnpm dev                     # http://localhost:3000
```

| Script            | What it does                                                        |
| ----------------- | ------------------------------------------------------------------- |
| `pnpm dev`        | Development server with hot reload                                  |
| `pnpm build`      | Production build (static page + `/api/lead` function)               |
| `pnpm start`      | Serve the production build locally                                  |
| `pnpm lint`       | ESLint (Next.js core-web-vitals + TypeScript rules)                 |
| `pnpm typecheck`  | Generate Next.js route types and run `tsc --noEmit`                 |
| `pnpm check`      | `lint` + `typecheck`                                                |
| `pnpm icons`      | Regenerate favicon / app icons from `app/icon0.svg` (uses `sharp`)  |

Requires Node.js 20.9+ and pnpm (the repo pins `pnpm@12` via `packageManager`).

## Project structure

The code is organised by concern so that copy, design, behaviour and delivery can change independently.

```

  page.tsx                The single page: composes sections + JSON-LD
  globals.css             Tailwind import + design tokens (light/dark) + base styles
  api/lead/route.ts       POST /api/lead — validates and forwards form submissions
  opengraph-image.tsx     1200×630 OG image generated at build time (twitter-image re-exports it)
  icon0.svg, icon1.png, apple-icon.png, favicon.ico   Favicon set (generated by `pnpm icons`)
  manifest.ts, sitemap.ts, robots.ts                  Web manifest, sitemap.xml, robots.txt
  privacy/, terms/        Placeholder legal pages (review with counsel)
  not-found.tsx           404

content/                  Everything a non-developer might edit
  site.ts                 All copy, section order metadata, nav, form labels, FAQ, footer
  code-samples.ts         API snippets shown in the hero and the developer section
  legal.ts                Privacy / terms copy
  icons.ts                Names of icons content may reference

components/
  sections/               One component per page section (Hero, Problem, HowItWorks, …)
  layout/                 Header, MobileMenu, Footer, LegalPage
  ui/                     Reusable primitives: Button, Card, Chip, Tabs, FaqItem, form controls, Reveal …
  illustrations/          Product-surface mocks built in code: CheckoutMock, ApiCallMock, PosPromptMock, UssdScreenMock
  forms/                  Lead forms (audit + developer), submission hook, shared form shell
  brand/                  Logomark and wordmark (SVG)
  analytics/              Analytics loader, click tracking, cookie-free notice
  seo/                    JSON-LD script component

lib/
  lead/schema.ts          Lead model + validation (shared by the client forms and the API route)
  lead/deliver.ts         Delivery transports: webhook, Resend (add a CRM here)
  seo/json-ld.ts          Organization / WebSite / Service / FAQPage builders
  seo/metadata.ts         Shared Open Graph / Twitter metadata
  code/tokenize.ts        Tiny syntax tokenizer used by the code blocks
  analytics.ts            `trackEvent()` and provider configuration
  env.ts                  Public environment with safe defaults
  defer.ts, lazy-hydrate.tsx   Keep non-critical JavaScript off the critical path
  hooks/                  useReducedMotion (hydration-safe), useTypewriter
```

Server components are the default; only interactive pieces (`Header`, `Reveal`, the mocks, tabs, forms, analytics) are
client components. Copy is never hard-coded in components.

## Editing copy

Open [`content/site.ts`](content/site.ts). Each section is a plain object (`hero`, `problem`, `howItWorks`, `useCases`,
`premiumModels`, `developers`, `compliance`, `whyInsurail`, `faq`, `leadCapture`, `footer` …). Change the text, save,
and the page updates. A few conventions:

- Section `id`s are the anchor targets used by the navigation (`nav.links`) and the CTAs.
- `icon` values must be one of the names in `content/icons.ts` (mapped to Lucide icons in `components/ui/Icon.tsx`).
- The FAQ also feeds the `FAQPage` structured data, so keep answers in plain prose.
- `site.title` should stay under 60 characters and `site.description` under 155.
- Code samples are in `content/code-samples.ts`. Keep lines short (≈60 characters) so nothing scrolls on mobile.
- Form option *values* live in `lib/lead/schema.ts` (they are validated); their labels live in `content/site.ts`.

## Connecting the lead form

Both forms (risk audit and developer early access) validate in the browser, then `POST` JSON to `/api/lead`.
The route re-validates with the same rules, drops submissions that filled the hidden honeypot field, and forwards the
lead to every transport configured through environment variables. If nothing is configured:

- in development the lead is printed to the terminal and the form shows success;
- in production the route returns 503 and the form shows an honest error with the contact email.

Set at least one of these in `.env.local` (or Vercel → Settings → Environment Variables):

| Variable                               | Purpose                                                                                       |
| -------------------------------------- | --------------------------------------------------------------------------------------------- |
| `LEAD_WEBHOOK_URL`                     | Any endpoint that accepts JSON: Formspree, Zapier, Make, n8n, HubSpot forms API, your CRM     |
| `LEAD_WEBHOOK_SECRET`                  | Optional. Sent as `Authorization: Bearer …` so your endpoint can reject other callers          |
| `RESEND_API_KEY`, `LEAD_NOTIFY_TO`     | Email each lead through [Resend](https://resend.com); `LEAD_NOTIFY_FROM` sets the sender       |

The webhook body is `{ …flatFields, lead: { type, name, email, … }, meta: { receivedAt, ip, userAgent, referer } }`.
Flat fields are included so form backends like Formspree show them as columns; CRMs can read the nested `lead`.

To add another destination (e.g. HubSpot, Attio, a Slack message) write a `Transport` in
[`lib/lead/deliver.ts`](lib/lead/deliver.ts) and register it in `configuredTransports()`.

Events tracked around the form: `form_submit`, `form_success`, `form_error` (with `kind`), plus `cta_click` on buttons.

## Analytics

Analytics are off unless enabled. Both options are cookie-free, so the site shows a small dismissible notice
rather than a consent banner.

| Variable                          | Effect                                                                |
| --------------------------------- | --------------------------------------------------------------------- |
| `NEXT_PUBLIC_PLAUSIBLE_DOMAIN`    | Loads Plausible for that domain (`NEXT_PUBLIC_PLAUSIBLE_HOST` if self-hosted) |
| `NEXT_PUBLIC_VERCEL_ANALYTICS=1`  | Loads Vercel Web Analytics (enable Analytics on the Vercel project first) |

Custom events are sent with `trackEvent()` in `lib/analytics.ts`. Server-rendered links and buttons are tracked
declaratively with `data-event="cta_click" data-event-cta="hero_primary"`; outbound links are tracked automatically.

## Deploying to Vercel (insurail.io)

1. Push this folder to a Git repository (the scaffold did not initialise git: `git init && git add -A && git commit -m "Insurail site"`).
2. In Vercel, **Add New → Project**, import the repository. Framework preset: Next.js. No build settings need changing.
3. Add environment variables from `.env.example` (at minimum a lead transport). `NEXT_PUBLIC_SITE_URL` should be `https://insurail.io`.
4. Deploy. Then **Settings → Domains → Add** `insurail.io` and `www.insurail.io` (redirect `www` to the apex).
   Point DNS at Vercel: an `A` record for `@` to `76.76.21.21` and a `CNAME` for `www` to `cname.vercel-dns.com`
   (Vercel shows the exact values). HTTPS is issued automatically.
5. Optional: enable Vercel Web Analytics and set `NEXT_PUBLIC_VERCEL_ANALYTICS=1`.

No `vercel.json` is needed. Security headers are set in `next.config.ts`.

The page is statically pre-rendered at build time; `/api/lead` runs as a serverless function. A pure `output: "export"`
was not used because the brief asks for an API route, which needs a server; if you ever want a fully static export,
point the forms straight at a form backend (Formspree etc.) and drop the route.

## Assumptions made

- **No real numbers, customers or testimonials** appear anywhere. Prices in the product mocks (₦150 delivery cover,
  ₦100/week hospital cash, order values) are illustrative and labelled as such on the Terms page.
- **API shape is illustrative.** Endpoints, fields and SDK method names in `content/code-samples.ts` are a plausible
  design, not a spec. Keep them in sync with the real docs at `docs.insurail.io` (placeholder link; set `NEXT_PUBLIC_DOCS_URL`).
- **Social links are placeholders** (`linkedin.com/company/insurail`, `x.com/insurail`) in `content/site.ts`.
- **Legal pages are templates** written to match what the site actually does (a contact form and optional cookie-free
  analytics). Have counsel review before launch.
- **Fonts** are self-hosted latin subsets of Inter (body) and Inter Tight (headings). The naira sign is outside the
  latin subset and renders from the system font; this avoids an extra 85 KB font file. See `assets/fonts/README.md`.
- **Analytics**: Plausible is wired through its script tag; Vercel Analytics through its script and event queue.
  If you prefer the `@vercel/analytics` package, replace `components/analytics/Analytics.tsx`.
- **Regulatory language** (NAICOM, NDPA) is descriptive and non-committal; nothing on the site promises a licence
  status or a claims SLA.

## Verification

Run locally before shipping:

```bash
pnpm check && pnpm build
```

The build was verified with Lighthouse 13 (mobile, simulated slow 4G, three runs): Performance 95–98,
Accessibility 100, Best Practices 100, SEO 100; desktop: 100 across all four. Layout was reviewed at 375, 768,
1280 and 1920 px in light and dark mode with no horizontal overflow, and the forms, menu, tabs, accordion and skip link
were exercised in a real browser. Details in [`CHECKLIST.md`](CHECKLIST.md).
